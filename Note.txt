1. Cơ bản về GIT:

clone: git clone  <link du an>
    -> main branch

new branch: git branch <ten branch>
    ex: git branch feature/order

Nhảy sang nhánh mới:
    git checkout <ten branch>
    ex: git checkout feature/order

Tạo file mới muốn add vào git
    git add <file path>
    git add . (ko neng dung lenh nay, de tranh add nham file khac)

Commit: git commit -m "noi dung commit"
    ex: git commit -m "add order service"

push len remote: git push origin <ten branch>
    ex: git push origin feature/order
2. Cách làm việc với pull request:
- Sau khi push code lên remote, vào github tạo pull request từ branch mới tạo sang main
- Đợi team review code, nếu có comment thì sửa lại code rồi push tiếp lên remote
- Sau khi được review và merge vào main, xóa branch cũ đi để tránh nhầm lẫn
- Nếu có nhiều pull request cùng lúc, nên đặt tên branch rõ ràng để dễ quản lý, ví dụ: feature/order, bugfix/login, hotfix/payment
- Khi làm việc với pull request, nên thường xuyên cập nhật branch của mình với main để tránh xung đột khi merge, có thể dùng lệnh: git pull origin main để cập nhật branch
- Nếu có xung đột khi merge, cần giải quyết xung đột bằng cách chỉnh sửa file bị xung đột, sau đó commit lại và push lên remote để tiếp tục
- Khi review code, nên chú ý đến các vấn đề như: code có dễ đọc không

- code có tuân theo quy tắc đặt tên không
- code có tối ưu không
- code có bảo mật không
- code có test không
- code có tài liệu không

ex: git pull (update project)

fetch: git fetch origin <ten branch>
    ex: git fetch
    -> ko tìm đc tên branch hoặc muốn cập nhật project

merge:
    git merge <ten branch>
    ex: git merge feature/order
    -> sau khi fetch về, muốn merge vào main để cập nhật project

input:
    placeholder: goi ys xem o day nhap cai j
    value: gia tri se dc dien mac dinh vao input
    name:
        ten cua input
    type:
        text: type mac dinh
        password: hien thi * thay vi raw value (gia tri tho)
        number: nhap so
        email: nhap email, check co "@" hay ko
        submit: nut bam, khi bam vao day thi verify dc email

    form:
        method: phuong thuc (post/get/put/patch/delete)
        action: hanh dong sau khi submit (url)
        exp: form(method="post" action="/login")


    dieu kien:
        - the form phai co tyction + method neu ko truyen method -> mac dinh la method GET
        - input type la submit
    hanh dong:
        khi bam nut submit, thi du lieu se dc gui link trong action voi method da dc dinh nghia

    get: du lieu dc gui qua url
        han che:
            - limit (tuy trinh duyet)
            - kem bao mat hon
          -> method mac dinh cua trinh duyet

    post / put / patch: du lieu dc gui ko qua url

    select - option
